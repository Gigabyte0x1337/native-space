# Licensing

Native Space uses separate licenses for software and research exposition.
This boundary is intentional: code remains available under strong network
copyleft, while the written theory remains reusable under share-alike terms.

## Software

Unless a file states otherwise with an SPDX identifier, source code, scripts,
tests, build definitions, and executable examples are licensed under the
**GNU Affero General Public License, version 3 or any later version**
(`AGPL-3.0-or-later`). The complete license is in
[`LICENSES/AGPL-3.0-or-later.txt`](LICENSES/AGPL-3.0-or-later.txt).

## Theory and documentation

Unless a file states otherwise with an SPDX identifier, research notes,
mathematical exposition, proofs, specifications, diagrams, and other
documentation are licensed under the **Creative Commons
Attribution-ShareAlike 4.0 International** license (`CC-BY-SA-4.0`). The
complete license is in
[`LICENSES/CC-BY-SA-4.0.txt`](LICENSES/CC-BY-SA-4.0.txt).

This includes the research notes and material under documentation-oriented
paths such as `README.md`, `theory/`, `proofs/`, `reconstructions/`,
`applications/`, and the Markdown files under `language/` and `examples/`.

## Data and third-party material

A dataset, model, external quotation, reproduced figure, or other third-party
material is governed by the notice shipped with that material. It is not
relicensed merely by being present in this repository. New data produced
entirely by this project must carry an explicit license or be covered by a
directory-level notice before publication.

## Mixed and ambiguous files

An explicit file-level SPDX identifier overrides the directory defaults above.
A file containing both substantial executable software and substantial
research exposition must state its license explicitly; contributors should
prefer separating those parts into independently licensed files.

If the scope remains genuinely ambiguous, do not redistribute the file until
the project has clarified its status. No contribution is accepted under
terms incompatible with the applicable project license.

## What these licenses do not cover

These licenses govern copyrightable software and expression. They do not turn
mathematical facts, discoveries, or independently created implementations into
project property. Patent, trademark, privacy, model-license, and third-party
data rights, if any, must be evaluated separately.

## Contributions

By contributing, a contributor agrees to license the contribution under the
license applicable to the destination file or directory, unless a different
written agreement is accepted before the contribution is merged.

This licensing notice is a project policy, not legal advice.
